# 《桌面小仙》游戏画面全面优化方案

> 版本 v1.0 ｜ 2026-10-06
> 适用范围：秘境 ARPG（`src/game/dungeon.ts` + `gl-world.ts` 2.5D 渲染层）与桌宠（`PetCanvas.tsx`）
> 前置依赖：已完成 2.5D 渲染层（commit 128a004）与 Bloom／区域色调／浮尘／软阴影增强（commit 24f6ca5）
> 说明：本方案全部结论来自对 119 个素材与渲染管线的**实测审计**，而非经验泛谈。

## 0. 现状实证审计

### 0.1 审计口径

对 `src/assets/` 全部 119 个素材逐个解析二进制头取得真实像素尺寸（PNG 读 IHDR、WebP 读 VP8/VP8L/VP8X、JPEG 读 SOF），并与代码中的**实际绘制高度**（`ENEMY_SPRITE_H`、`propH`、`syncCompanion` 等）逐项比对。

**核心指标 —— 纹理充足率**：

```
纹理充足率 = 源图边像素 ÷ (绘制高度(世界单位) × devicePixelRatio)
```

绘制高度单位是「世界单位」，经 `worldToScreen` 1:1 映射到逻辑画布，再按 dpr 落到物理像素。取 **dpr = 2**（HiDPI 主流场景，也是 `gl-world.ts` 的上限）为基准：

- < 1.0 → **欠采样**，必糊
- 1.0 ~ 1.5 → 偏软
- ≥ 1.5 → 达标
- ≥ 2.0 → 优良（主角 / Boss 建议值）

|---|---|---|---|
| 主角 / 皮肤 | 54 | 统一 512×512 webp | ~5.5MB |

| **合计** | **119** | | **19MB** |

### 0.3 六大核心缺陷（按 ROI 排序）

**① 妖皇 Boss 是全场唯一「欠采样」素材 —— 最该清晰的角色却最糊**

妖皇源图仅 256×256，却在 `ENEMY_SPRITE_H` 中被绘制到 150 世界单位（同级 Boss 冰君／蛊君为 160／165）。dpr=2 下需要 300px，**充足率仅 0.85**。而它恰恰是游戏的视觉核心（Boss 登场卷轴题名 + 决战演出）。

**② 精度梯队混乱，同一「Boss 阶」源像素相差 3 倍**

| 阶 | 素材 | 源 | 说明 |
|---|---|---|---|
| Boss 阶 | 妖皇 | 256 | ✗ 与同级相差 3 倍 |
| Boss 阶 | 冰君 / 蛊君 | 768 | ✓ |
| 精英 | 石人 | 256 | △ 绘制 100，充足率 1.28 偏软 |
| 精英 | 冰蛇／霜蛾／蛊虫／蚕／蟾 | 512 | ✓ |
| 小怪 | 狼／蛛／灵体 | 256 | 绘制 54~64，充足率 2.0+ 尚可 |

**③ 地面地块是所有场景的画质天花板**

4 张地块仅 512×456（雪地 1024×1024，长宽比还与其他不一致）。`drawGroundRegion` 用 `createPattern(img,'repeat')` **原尺寸**平铺：视口宽 1280 世界单位 ÷ 512 = **屏幕内仅重复 2.5 次**，重复感明显；且地砖被烘进 dpr=2 的地面画布后，每个源像素被拉成 2 个物理像素 → 地面整体发软。世界 4200×2900 全域仅约 52 块砖，缺乏中观层次。

**④ 零序列帧 —— 全部 119 个素材都是单张静态图**

这是「动画不够流畅」的根因。目前所有动效都只是**程序化变换**：

- 行走：`walkT` 相位驱动的 `Math.sin` 上下浮动
- 挥剑：`swingT` 0.22s 计时 + 前冲位移
- 受击：整体缩放／透明度闪烁

没有任何一帧真正的角色动画。全项目仅有桌宠 `packs.ts` 的 frames 机制，且实际只用到 **2 帧 @ 1.8fps**（学习来回两张图）。

**⑤ AI 陪伴角色「仙友·小满」没有自己的立绘**

`dungeon.ts:333`：`companionImg.src = pet.gender === 'male' ? petBattleUrl : petBattleMUrl`
—— **仙友直接复用主角贴图**。在玩家眼里仙友就是「第二个自己」，仅靠粉色名字与称谓区分。这是陪伴系统视觉说服力不足的直接原因。

**⑥ 角色不参与场景光照（Sprite 与场景色调脱节）**

已实现的区域色调（commit 24f6ca5）只作用于**雾色 + 天幕**，原因是 `SpriteMaterial` **不接收** `HemisphereLight`/`DirectionalLight`，立绘只有远处受雾影响。结果：走进紫色瘴疠林时，地面和雾都变紫了，**角色仍是一身原色**，像贴片。

**附带发现**：37 个 PNG 与同名 WebP 完全重复（已全部转码），**冗余 11MB，占资产总量 58%**，且全部未被代码引用。

## 1. 素材分类优化方向

每个类别统一按五个维度推进：**① 贴图分辨率与质感 ② 造型精细度 ③ 动画流畅度 ④ 特效表现 ⑤ 光影与配色统一性**

### 1.1 主角（含男／女相、皮肤、灵翼、坐骑）

| 维度 | 现状 | 优化方向 | 目标值 |
|---|---|---|---|
| **贴图分辨率** | 512×512，充足率 3.76 —— **已达标，无需放大** | 维持 512，转向「同分辨率下的质感提升」 | 充足率保持 ≥ 3.0 |
| **质感** | 厚涂 Q 版，WebP 约 q80 | 统一为 **512 WebP q88**（去除 alpha 抖动）；导出前做轻微锐化（USM 0.4px）以抵消 2.5D 斜视软化 | 边缘锐利无毛边 |
| **造型精细度** | 单张正面 | 增补**眨眼帧**（已有 blink 版）+ 张嘴／受惊变体；男／女相各自补齐 | 每状态 ≥ 2 个变体 |
| **动画流畅度** | 0 帧，全靠 sin 摆动 | **引入序列帧**（见 1.6）：待机 6~8 帧、行走 8 帧、挥剑 6 帧、冲刺 4 帧、受击 2 帧；闪避残影沿用现有 ghosts | 移动 ≥ 12fps，攻击 ≥ 20fps |
| **特效** | 剑光为程序化月牙 + 纯色粒子 | 生成 PNG 序列 VFX：出剑弧光、冲刺残影拖尾、受击星火、突破光柱 | 每套 6~8 帧 @ 24fps |
| **光影统一** | 不吃场景光 | 用 `SpriteMaterial.color` 乘区域环境色，并叠加加色 rim 副本（见 1.5 技术方案） | 角色随区域染色 |

**灵翼／坐骑**：512 源，绘制约 134 → 充足率 1.91，**临界**。建议重出到 640 或降低放大系数，并为坐骑补「骑行／待机」两态。

### 1.2 AI 陪伴角色（仙友·小满） —— 从 0 到 1

| 维度 | 现状 | 优化方向 |
|---|---|---|
| **贴图** | ✗ 复用主角 | **新建专属立绘**：少女／道童形象，与主角同画风（厚涂 Q 版）但色相区隔（建议粉青 vs 主角青绿）。绘制仅 56，512 源即可 |
| **造型** | 无 | 提供 idle / battle 两态，并补「施法」pose（仙友会出手），与其台词逻辑联动 |
| **动画** | 跟随主角摆动 | 引入 8 帧行走 + 6 帧施法序列帧，不再跟着主角浮动 |
| **特效** | 无 | 专属**灵蝶／光点**环绕加色粒子（区别于主角的剑气星火），让「陪伴」被看见 |
| **配色** | 与主角相同 | 明确 #ffc4dd 粉系主色，与其名字颜色呼应，并与区域色做和声而非喧宾夺主 |

### 1.3 怪物（12 种）

**P0 —— 先补「糊」的三处硬伤**

| 对象 | 源 → 目标 | 理由 |
|---|---|---|
| 妖皇 boss | 256 → **1024** | 充足率 0.85 → 3.4，决战的脸面 |
| 石人 golem | 256 → **512** | 1.28 → 2.56 |
| 石碑 stele（奇遇） | 256 → **512** | 绘制 116，充足率 1.10 → 2.2 |

**统一分辨率梯队（新增贴图规范）**

| 阶 | 源分辨率 | 成员 |
|---|---|---|
| 小怪 | 512 | 狼、蛛、灵体、蛊虫、蚕、霜蛾 |
| 精英 | 640 | 石人、冰蛇、蟾 |
| Boss | **1024** | 妖皇、冰君、蛊君（统一，消除 3 倍极差） |

**动画**：每种怪至少 **idle 6 帧 + move 8 帧 + attack 6 帧 + hurt 2 帧 + death 8 帧**。
Boss 额外增加：出场演出 8 帧、暴走形态变体（`dungeon.ts:1155`「它暴走了」已有配套逻辑，但目前没有对应素材）。

**光影与配色统一性**：怪物需与所属区域色调呼应（瘴疠林怪偏紫、寒潭怪偏蓝），并统一光照方向 —— 目前场景阳光来自左上 `(-0.62, 0.7, 0.35)`，但各立绘高光方向各异，需在出图规范里写死「主光左上 45°、暖补光右上」。

### 1.4 场景（地面 / 装饰 / 奇遇物件 / 天幕）

**地面（最高优先级的场景项）**

| 维度 | 现状 | 优化方向 |
|---|---|---|
| 分辨率 | 512×456（雪 1024） | 全部统一 **1024×1024 无缝**，取消非标准长宽比 |
| 平铺密度 | 屏内 2.5 次 | 世界绘制单位下调至地块的约 45%，屏内重复 **≥ 5 次**，观感细节密度同步提升 |
| 层次 | 单层 pattern | 三层叠加：**1024 基底地块 + 中观噪波层（打破重复）+ 区域边缘磨损贴花** |
| 变体 | 每区 1 张 | 每区提供 **A/B 两张可混叠** + 1 张 alpha 贴花，消除全域 52 块砖的重复感 |
| 存量 | — | 雪地已有 1024，其余 4 张（forest／swamp／barren／lava）重制或替换为 CC0 素材 |

**装饰（竹／枯树／剑碑／晶簇／冰莲）**：256 → 统一 **512**；并补同族变体（每种 2~3 个高度／形态），解决「整片竹林一个模子」。装饰同为 Sprite，同样受益于下文的统一着色方案。

**奇遇物件**：herb／chest／stele 256 → **512**（stele 优先，因充足率仅 1.10）；新增**交互发光态**（当前仅靠 opacity 0.22／1 区分，辨识度弱）。

**天幕**：现为 16×256 的纯程序渐变，过于简陋。方向：**2048×1024 手绘远山剪影 + 体积云**，做 2~3 层视差（`sky.position` 现已随相机移动，天然支持）。

### 1.5 特效

| 现状 | 优化方向 |
|---|---|
| 弹幕／落雷／预警环全是几何体 + 纯色 | 换成**序列帧贴图**：雷法 8 帧、Boss 技能 12 帧 |
| 粒子为单像素点（size 7） | 生成**软圆／星芒／火花／烟**四张图集，把 `PointsMaterial` 换成带柔和 alpha 的图集粒子 |
| 无命中反馈 | 增补刀光：命中瞬间径向白闪 + 冲击波环 + 飞溅碎片 |
| 无环境 VFX | 按区域补齐：竹林飘叶、毒沼气泡、炎窟余烬、寒潭飘雪、瘴疠林鬼火 |

### 1.6 素材来源策略：自生成 vs 下载

> 授权底线：**只引入 CC0 或许可明确可商用的素材**，所有引入项登记到 `docs/LICENSES-3RD-PARTY.md`。下载前逐个确认许可，不批量导入。

**判断规则（关键）：「风格一致性」优先交给生成，「物理真实性」优先交给下载。**

| 素材 | 方式 | 理由与执行 |
|---|---|---|
| 主角／仙友／怪物立绘与序列帧 | **自生成**（ImageGen） | 厚涂 Q 版是项目唯一画风，外部下载必然风格冲突。按 1.1／1.2／1.3 的出图规范批量产出 |
| VFX 序列帧（刀光／雷法／水花／烟） | **自生成** | 同上，且 VFX 需与角色色板同色系 |
| UI 图标 / 图鉴格 | **自生成** | 与整体 UI 语言保持一致 |
| **地面地块等写实质感纹理** | **优先下载** | 「无缝平铺 + 真实噪波」是图像生成的弱项，容易接缝违和。建议取自 **ambientCG**（CC0，含 Ground／Forest／Rock／Snow／Sand，原生无缝且带 normal／roughness 贴图） |
| 远景天幕云层／山剪影 | **下载 + 二次加工** | Poly Haven（CC0 HDRI）、ambientCG；下载后重新校色调以贴合区域色（项目现成的 `regionTint` 机制可直接复用） |
| 环境动态元素（落叶／雪／灰烬） | 混合 | 贴图下载自 ambientCG，运动逻辑自写（已有 motes 骨架，直接换贴图） |
| 通用 UI 音效（可选） | 下载 | Kenney CC0 Audio pack |

推荐 CC0 源站（逐个校验许可）：`ambientcg.com`、`polyhaven.com`、`kenney.nl`、`opengameart.org`（需按 CC0 过滤）。

## 2. 整体画面提升的量化目标

### 2.1 素材质量

| 指标 | 现值 | 目标 | 验收方式 |
|---|---|---|---|
| 欠采样素材数（充足率 < 1.0） | **1**（妖皇 0.85） | **0** | 脚本重算充足率表 |
| 充足率 < 1.5 的素材数 | 3（妖皇／石人／石碑） | **0** | 同上 |
| 主角／Boss 充足率 | 3.76 / 0.85 | **≥ 3.0 / ≥ 2.5** | 同上 |
| Boss 阶分辨率极差 | 768−256 = 512（3 倍） | **0（统一 1024）** | 同上 |
| 地面地块分辨率 | 512（仅 1 张 1024） | **1024 全覆盖** | 同上 |
| 屏内地面重复次数 | 2.5 | **≥ 5** | 截图目视 + 铺贴脚本核算 |
| 资产总量 | 19MB | **≤ 12MB**（清 11MB 冗余 + 引入约 4MB 新素材） | 目录体积 + 构建产物体积 |

### 2.2 动画

| 指标 | 现值 | 目标 |
|---|---|---|
| 帧动画覆盖率（战斗内实体） | **0%** | **100%**（玩家／仙友／12 种怪） |
| 待机 / 行走 / 攻击帧数 | 0 | 6~8 / 8 / 6 |
| 战斗动画采样率 | 约 0（程序化 sin） | 移动 ≥ 12fps，攻击 ≥ 20fps，受击／死亡 ≥ 15fps |
| 每种实体的动作状态数 | 1（单图） | ≥ 5（idle／move／attack／hurt／death） |

### 2.3 光影与色彩统一性

| 指标 | 现值 | 目标 |
|---|---|---|
| 角色参与场景光照 | **否**（Sprite 不吃光） | **是**（区域色调 + 统一主光方向） |
| 立绘主光方向一致性 | 各异 | 统一左上 45° 主光 + 右上暖补光（写进出图规范） |
| 区域氛围过渡平滑度 | lerp 0.04（已实现） | 保持，并扩展到角色与装饰 |
| Bloom 覆盖的发光元素 | 有（Bloom 已接 render） | ≥ 90% 的亮特效走加色 + Bloom |

### 2.4 性能预算（画质提升不能换来卡顿）

| 指标 | 目标 | 说明 |
|---|---|---|
| 帧率 | 1080p / 中端集显 ≥ **55fps** 稳定 | 以冒烟采样为准 |
| Draw call | 增幅 ≤ 15% | 序列帧必须用**图集 + 共享材质**，不得每帧新建纹理 |
| 显存 | ≤ **220MB** | 引入 1024 Boss 图／地块后核算 |
| 加载时间 | ≤ 现值 + 0.5s | 地面与低频地块按需加载 |

## 3. 分阶段实施流程

> 每阶段都以「上一阶段截图」为基线做 A/B 对比，不可跳阶段。**每个阶段产出独立 deliverable，可单独提交或回滚。**

### P0 · 基准与清理（0.5 天）

**目标**：建立可度量的画质基线与对比工具；清掉纯冗余。
- 保留 `scripts/audit-assets.cjs` 作为常驻校验脚本（输出充足率表），纳入 npm scripts（建议 `"audit:assets": "node scripts/audit-assets.cjs"`）
- 删除 37 个未被引用的同名冗余 PNG（**−11MB**），仓库外保留源图备份
- 建立「画质对比台」：固定种子 + 固定相机位置的截图脚本（5 个代表性场景：青竹林／毒沼／寒潭／炎窟／Boss 房），产出 P0 基线组图
- 新增 `docs/LICENSES-3RD-PARTY.md`，建立第三方素材登记规范

**交付物**：充足率报告、P0 基线截图 ×5、精简后的 assets 目录、登记规范
**验收**：`tsc -b` 通过；冒烟 PASS；资产 19MB → 8MB

### P1 · 精度补齐 —— 先治「糊」（2 天）

**目标**：消灭全部欠采样与偏软素材，统一分辨率梯队。
- 重出妖皇 1024、石人 512、石碑 512（自生成，prompt 锁定画风与主光方向）
- 按 1.3 梯队表重出小怪 512 / 精英 640
- Boss 阶统一 1024，消除 3 倍极差
- 地面 4 张地块升级 1024 无缝（下载 CC0 后调色，做无缝校核）
- 装饰与奇遇物件统一 512，每种补 2~3 个变体

**交付物**：替换后的立绘／地块／装饰素材 + 更新后的充足率表（全绿）
**验收**：充足率全部 ≥ 1.5，Boss ≥ 2.5；A/B 截图目视 Boss 由糊转锐利

### P2 · 序列帧动画上线（3 天）

**目标**：让画面真正「动起来」，这是观感提升最大的一步。
- 实现**图集动画层**：扩展 `gl-world.ts` 的 billboard，支持 `SpriteSheetAnimation`（行列切帧 + fps + 循环/单次 + 事件回调）
- 动作状态机 `animState: idle | move | attack | hurt | death`，由现有 `walkT`／`swingT`／hitstop 驱动切换
- 产出帧表：玩家（含仙友）6+8+6+2+8；12 种怪各按 P1 新形象补同规格帧
- **性能约束**：全部走单纹理合图，共享 `SpriteMaterial`，draw call 增幅 ≤ 15%

**交付物**：动画图集、`SpriteSheetAnimation` 模块、状态机、对比视频／GIF
**验收**：100% 战斗实体有帧动画；高帧率录屏下动作连续无跳帧；满足 2.4 性能预算

### P3 · 场景与光影统一（2.5 天）

**目标**：让角色「长在场景里」。
- **角色与装饰入场光照**：所有 Sprite 叠加区域色 multiply + 加色 rim，跟随已实现的 `regionTint` lerp
- 地面三层叠加：基底地块 + 中观噪波（打破重复）+ 边缘磨损贴花
- 天幕升级：2048 远山云影 + 2~3 层视差
- 补齐奇遇物件的交互发光态

**交付物**：统一着色工具函数、地面三层实现、新天幕、P3 完成后组图
**验收**：走进瘴疠林时角色／地面／雾**三者同色调**；地面无肉眼可见重复；各场景组图对比

### P4 · 特效与后处理升级（2 天）

**目标**：打击感与「仙气」。
- 引入 VFX 序列帧：出剑弧光、冲刺残影、受击星火、突破光柱、Boss 技能预警
- 粒子系统升级：单像素点 → 四合一图集（软圆／星芒／火花／烟）
- 环境动态：竹林飘叶 / 毒沼气泡 / 炎窟余烬 / 寒潭飘雪 / 瘴疠林鬼火（复用现有 motes 骨架）
- Bloom 参数按区分档微调（炎窟强、寒潭弱）

**交付物**：VFX 图集与实现、环境动态效果、按区分档的 Bloom 配置
**验收**：连击录屏无明显丢帧；每类场景至少有 1 个专属环境动态效果

### P5 · 验收与调优（1 天）

- 三轮针对性调优

**交付物**：验收报告、最终截图对比、**commit + 推送**
**验收**：所有量化指标达成；无功能回归；相关文档回写

## 4. 优化后预期视觉效果

**① 角色：从「会动的立绘」到「在场的角色」**
主角与仙友各自真正动起来 —— 走动时有步伐交替与衣袂摆动，出剑是 6 帧的蓄力→挥砍→收势（而非一个 0.22 秒的数值动画），受击有短促后仰。仙友有了自己的脸：粉色系少女形象，身边绕着专属灵蝶粒子，施法时有自己的出手动作 —— 陪伴第一次「被看见」。

**② Boss 战：从「糊成一团」到「压迫感」**
妖皇贴图从 256 升到 1024 并补足出场／暴走两态后，登场卷轴展开的瞬间，玩家第一次能看清它的面部细节与甲片质感；配合专属的技能预警 VFX 与 Bloom 辉光，决战终于有了「终局感」。Boss 阶统一到 1024 后，妖皇／冰君／蛊君并陈时不再有清晰度落差。

**③ 场景：从「贴片地面」到「有纵深的空间」**
地面不再是一张 512 图无缝重复 —— 三层叠加带来近观有颗粒、中景有起伏、远处有边界磨损的层次感；屏内重复从 2.5 次提升到 5 次以上后，「一眼看出是同一块图」的廉价感消失。天幕有了真实的远山云影与视差，随推进缓慢位移。

**④ 整体：从「各自为政」到「统一的光与色」**
最关键的变化 —— 走进瘴疠林时，不仅雾变紫，主角、仙友、怪物、装饰的服饰都被同一束区域环境光染上紫色氤氲，且所有立绘的高光统一来自左上 45°，彼此终于处在同一个物理空间里。这是「看起来贵」与「看起来像拼贴」的分水岭。

**⑤ 性能不打折扣**：显存 ≤ 220MB、draw call 增幅 ≤ 15%、1080p 集显 ≥ 55fps —— 画质提升不靠堆开销，靠的是「补足缺失、消除冗余、统一规范」。

## 5. 风险与回滚

| 风险 | 缓解措施 |
|---|---|
| 序列帧产出量大（12 种怪 × 5 状态） | 分批推进：P2 先覆盖玩家 + 仙友 + 4 种高频小怪 + 3 个 Boss，其余后续补齐；优先级按怪物出没频率排序 |
| 图集导致 draw call / 显存上升 | 强制合图 + 共享材质；P2 结束即跑性能核验；超预算则缩减优先级低的装饰变体 |
| 第三方地块与手绘角色风格冲突 | 下载后必须过一道「调色工序」统一到项目色板；先在单个区域做灰度样板验证再全线铺开 |
| 许可风险 | 只用 CC0；所有引入登记到 `LICENSES-3RD-PARTY.md`；许可存疑的一律改用自生成 |
| 新出图与旧画风不一致（尤其是主角） | 主角**沿用现有 512 形象作为参考图**，只补帧不重画；凡是「补帧」都必须带参考图锁定画风 |
| 阶段失败影响面 | 每阶段独立 commit 推送，始终保留 P0 基线；任一阶段不达标即停下，不影响已上线部分 |
